# Воспроизведение нейросетевых экспериментов

Это отдельное исследование прогноза количества эпизодов за следующие 24 часа. Оно не меняет рабочий API и активную модель. Результаты и решение об отборе описаны в [RESEARCH_GOAL90.md](RESEARCH_GOAL90.md); машиночитаемые метрики включены в `artifacts/goal90_research_report.json`.

## Среда

Используется Python 3.12 и необязательная зависимость PyTorch 2.14. Создайте среду из корня проекта:

```bash
python3.12 -m venv .venv-neural
.venv-neural/bin/python -m pip install -r requirements-neural.lock
PYTHONPATH=src .venv-neural/bin/python -m pytest -q
```

В выполненном локальном эксперименте отдельная среда использует уже установленные научные пакеты основной `.venv` через локальный `.pth`; PyTorch и его дополнительные зависимости установлены только в `.venv-neural`. Этот локальный файл с абсолютными путями не входит в поставку. Для чистого развёртывания предназначена команда установки полного lock-файла выше. Основные пакеты и `requirements.lock` не менялись.

До получения результатов на данных выполнен синтетический замер CPU и Apple GPU. На этой машине выбран `mps`: 0,00248 с на шаг против 0,00369 с на CPU. Это короткий технический замер GRU, а не оценка полного времени обучения или качества. Отдельно проверены прямой и обратный проходы обеих настоящих сетей, совпадение прямого прохода с CPU и восстановление прерванного обучения. Результат зафиксирован в `artifacts/neural_compute_preflight.json` и включён в хеши плана. В ограниченной песочнице MPS может быть недоступен; проверка и обучение выполнялись с доступом к локальному GPU.

## Данные и запуск

Нужна полная подготовленная история, включая `features-channel-novelty.parquet`, `features-dense-channel-novelty.parquet`, `episodes.parquet`, а также замороженные исследовательские модели и прогнозы предыдущих серий. Точные пути и SHA-256 перечислены в `artifacts/research-v28/plan.json`. Минимальный runtime-архив содержит только данные для демонстрации и не заменяет полный исследовательский набор.

```bash
PYTHONPATH=src .venv-neural/bin/python -m moscollector.neural_count_research --stage screen --device mps
PYTHONPATH=src .venv-neural/bin/python -m moscollector.neural_count_research --stage confirm --device mps
```

Вторая команда допускается только после завершения отбора всех трёх направлений. Дополнительные месяцы оцениваются только для прошедших отбор направлений. Если никто не проходит, команда лишь формирует итоговый отчёт. Для другой машины или нового вычислительного устройства задайте новую папку через `--output`, например `--output artifacts/research-v28-cpu --device cpu`. Устройства `cpu`, `mps` и `cuda` предусмотрены интерфейсом, но в этой серии проверены только CPU и MPS. Работа на CUDA не заявляется как проверенная. Самопроизвольного перехода с GPU на CPU нет. Путь к исходному техническому замеру остаётся в плане; новое устройство явно записывается отдельно и не выдаётся за исходный MPS-эксперимент.

На кластере обучение должно запускаться через `sbatch` на вычислительном узле. Скрипт `train_native.sbatch` из другой задачи не входит в этот проект и не используется здесь. Кластерный запуск для v28 не выполнялся.

## Восстановление и проверка

Повтор той же команды с той же папкой продолжает обучение с последней завершённой эпохи. `last.pt` атомарно хранит веса, состояние AdamW, лучшую эпоху и счётчик остановки. `model.pt` содержит веса лучшей валидационной эпохи; `fit.json` — конфигурацию, размеры выборок, число разных доступных эпизодов, историю потерь и хеш весов. Эпизоды могут быть зависимы во времени и между объектами. Подмена кода, входов, устройства или конфигурации требует новой папки исследования.

История каждой последовательности содержит не более 16 исходных трёхчасовых наблюдений того же объекта в интервале `[t−48ч, t)`. Текущий момент, будущее, признаки целевой переменной и исторический флаг доступности не участвуют в отборе истории. Нормализация и словари категорий строятся на обучающем периоде. Тесты проверяют эти ограничения, пропуски, неизвестные категории и точное восстановление маленького прерванного обучения на CPU/MPS. Побитовое совпадение обучения между разными устройствами и машинами не обещается.

Сети MLP и GRU используют одинаковый текущий снимок и общие правила обучения. GRU получает дополнительную историю; число параметров различается. Поэтому её возможный выигрыш сам по себе не доказывает, что причина именно в порядке наблюдений. Событийные метрики сравниваются также с замороженным CatBoost при одинаковых объектах, эпизодах, калибровке и политике предупреждений. Перекрывающиеся положительные окна не считаются независимыми происшествиями.

После завершения исследования `scripts/summarize_goal90.py` проверяет входы и код плана, веса сетей, кодек, устройство и согласованность результатов. Июньский исходный тест не открывается повторно. Метки остаются сгруппированными сигналами датчиков; качество на них не равно качеству выявления подтверждённых физических аварий.

Описание использованных компонентов: [GRU](https://docs.pytorch.org/docs/2.14/generated/torch.nn.GRU.html), [PoissonNLLLoss](https://docs.pytorch.org/docs/2.14/generated/torch.nn.PoissonNLLLoss.html), [MPS](https://docs.pytorch.org/docs/2.14/notes/mps.html).

## Смеси прогнозов v29

Следующая проверка использует сохранённые прогнозы v28. Заранее заданы три смеси: CatBoost/MLP поровну, CatBoost/GRU поровну и все три модели с равными весами. Одни и те же веса отдельно смешивают уже откалиброванные вероятности и ожидаемые количества. Объединённый прогноз проходит обычное причинное правило выдачи предупреждений; готовые предупреждения моделей не складываются. Новых обучаемых весов смешивания или дополнительной калибровки нет.

```bash
.venv/bin/python scripts/audit_neural_complementarity.py
.venv/bin/python -m moscollector.neural_blend_research --stage screen
PYTHONPATH=src .venv-neural/bin/python -m moscollector.neural_blend_research --stage confirm
```

Первый этап работает в основной среде на CPU. Второй формирует отчёт и только для прошедших отбор направлений обучает дополнительные контрольные MLP/GRU по неизменной процедуре v28 на прежнем устройстве. Они сохраняются отдельно в `artifacts/research-v29/controls`; отчёт v28 не переписывается. При отсутствии прошедших отбор вариантов дообучения нет. Для продолжения используется та же команда и папка; входы и код защищены планом, а контрольные нейросети — прежними контрольными точками.

Аудит пересечения использует уже известные исходы событий исключительно для описания ошибок. Объединение найденных разными моделями эпизодов не является качеством доступного в реальном времени ансамбля и не устанавливает предел для новых прогнозов. Итоговая смесь должна улучшить критерий обеих метрик более чем на 5% относительно CatBoost, исторического ориентира и каждой входящей в неё нейросети без снижения F1. Правила отбора и последующего подтверждения зафиксированы до расчёта результатов смесей.

## Предварительное обучение на телеметрии v31

Проверяется та же GRU v28, но её обработчик истории сначала учится предсказывать текущие динамические признаки по прошлым наблюдениям. Текущий снимок служит целью этого этапа и не подаётся на вход сети. Из целей исключены календарь, статическое оборудование и признаки `past_*`, построенные по прошлым эпизодам. Сами исторические входы остаются прежними, включая уже известную информацию о прошлых эпизодах. Будущие 24-часовые метки не входят в предварительную функцию потерь.

Используются прежние обучающие и валидационные строки, нормализация, временные разрывы и максимум 16 наблюдений за 48 часов. Новые или внешние данные не добавляются. Пропущенные целевые ячейки и строки без истории исключаются из потерь. Функция [SmoothL1](https://docs.pytorch.org/docs/2.14/generated/torch.nn.SmoothL1Loss.html) с `beta=1` усредняется по наблюдаемым ячейкам. До восьми эпох, остановка после двух без улучшения; разрешена исходная нулевая эпоха. На тех же валидационных ячейках сохранены два простых ориентира: обучающее среднее и последнее прошлое значение с заменой его пропусков обучающим средним.

После этого переносится только проекция истории и GRU. Декодер телеметрии отбрасывается, остальные части прогнозной сети создаются с прежним seed 42; тест и проверка во время запуска подтверждают, что перенос их не меняет. Состояние оптимизатора не переносится. Затем вся сеть обучается по прежней Poisson-цели, максимум 20 эпох с терпением четыре. Число параметров и входы при прогнозировании совпадают с обычной GRU. Дополнительные шаги обучения расходуют больше вычислений: этот эксперимент не отделяет эффект предварительной задачи от эффекта большего бюджета оптимизации.

```bash
PYTHONPATH=src .venv-neural/bin/python -m moscollector.self_supervised_count_research --stage screen
PYTHONPATH=src .venv-neural/bin/python -m moscollector.self_supervised_count_research --stage confirm
```

Устройство и версия PyTorch наследуются из замороженного плана v28. Для каждого направления проверяется один вариант без подбора архитектуры по результатам. Отбор требует прироста совместного критерия более 5% без снижения F1 против обычной GRU, CatBoost и прежнего исследовательского ориентира. Периоды, калибровка, 456 политик предупреждений и состав эпизодов совпадают с контролем. Дополнительные месяцы разрешены лишь прошедшим отбор направлениям. Уже имеющиеся контрольные сети неисправностей берутся из v29; недостающие контрольные сети обучаются по процедуре v28 в отдельной папке v31.

Оба этапа независимо сохраняют атомарные контрольные точки. Хеши весов и метаданных предварительного этапа входят в подпись обучения прогнозной сети. Тесты проверяют маски пропусков, отсутствие зависимости от 24-часовых меток, перенос только нужных весов и точное восстановление обоих этапов после прерывания на CPU/MPS. Улучшение предсказания телеметрии само по себе не является улучшением Precision или Recall; решение принимается только по событийной проверке.

После завершения всех пяти периодов прошедших отбор неисправностей выполняется описательный разбор ошибок:

```bash
.venv/bin/python scripts/audit_self_supervised_fault_errors.py
.venv/bin/python scripts/summarize_goal90.py
```

Аудит повторно сверяет все метрики и состав эпизодов новой сети, обычной GRU и CatBoost. Он группирует эпизоды по давности предыдущего подтверждённого события в последнем доступном прогнозном снимке не позже начала эпизода. Подтверждение доступно лишь с целого часа после 70-минутной задержки, как в исходной политике. Такая группировка описывает уже известные исходы; она не меняет порогов, не исключает трудные события и не задаёт предел достижимого качества.
